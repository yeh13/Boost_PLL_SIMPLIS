## 3. Scaling：已知值與尚未能確認的 exact setting

目標：
`clip(round(2048 + 1860*Vin), 0, 4095)`。

LSB = 1/1860 = **0.0005376344086021505 V**。
理想 code center：Vin(code) = (code-2048)/1860。
code 0 center = -1.1010752688172043 V。
這個 code-zero center **不能直接填到 Generic ADC OFFSET**：官方定義的 OFFSET 是 range midpoint，不是 SystemDesigner 的 Input Offset。

**重要缺口：查到的 8.3 欄位表、官方 operation 圖與本機 schematic，沒有明列 Generic ADC 的完整量化方程式、half-LSB transition 與 tie 規則。尚未取得其 autogenerated model 的實際 threshold 定義。因此本文件不能聲稱已確認能 exact 等同 MATLAB round 的 RANGE/OFFSET。**

不能只用 Vin=0 -> 2048 就認定設定正確；floor 與 nearest 在整數中心都可能相同。

供 ADC-only 校準使用的 nominal range：
`4096/1860 = 2.2021505376344086 V`。
這是按 4096 uniform bins 推導的待確認值，不是已驗證的 device equation。

必須從 GUI 產生的 ADC netlist/model 確认 bin width 與 thresholds，或執行以下 DC 校準，再決定正式 OFFSET。以下是條件推導，不可盲選：

- 若實際公式為 clip(round((Vin-OFFSET)*4096/RANGE + 2048))：OFFSET=0。
- 若實際公式為 clip(floor((Vin-OFFSET)*4096/RANGE + 2048))：OFFSET=-0.5/1860 = -0.0002688172043010753 V。
- 若實際分母或邊界規則不同，以上兩式都不成立，應依 model 重算，不改 DUT 配合。
- 精確半碼點還須確認 tie 方向；不能僅靠遠離 threshold 的幾個 DC 點宣稱全域 bit-exact。

ADC-only 校準時 DUT reset 保持 1；每次換 DC 值，重新開始模擬，在 conversion 完成後讀 bus。IC=2048 不算 conversion 結果。其 expected 僅由使用者 ADC mapping 算出，不是 PLL golden 的替代：

|---|---:|
| -1 V | 188 |
| 0 V | 2048 |
| +1 V | 3908 |
| -0.75/1860 V | 2047 |
| -0.25/1860 V | 2048 |
| +0.25/1860 V | 2048 |
| +0.75/1860 V | 2049 |
| (100.49-2048)/1860 V | 100 |
| (100.51-2048)/1860 V | 101 |

| (3900.51-2048)/1860 V | 3901 |

加測 (n+0.5-2048)/1860 的精確 tie（例如 n=100、2048），期望 n+1。需把 analog 精度與 converter tie 規則分開記錄。取得 generated model 的方程式後才能把本節升級成 confirmed exact settings。

## 5. 唯一 master 與 deterministic scheduling

只有一顆 native Digital Pulse Source 作為 40 kHz master。DUT clock 來自同一條 clock 經 native **Buffer** 延遲；不用第二顆 oscillator，不用 timer wrapper。

建議 testbench 啟動原點 T0=1 us：

| 元件 | 設定 |
|---|---|
| master Digital Pulse Source | PERIOD=25u、WIDTH=12.5u、DELAY=1u、VOL=0、VOH=5、ROUT=10；normal output |
| DUT clock Buffer | DELAY=100p、IC=0、VOL=0、VOH=5、TH=2.5、HYSTWD=1、RIN=10Meg、ROUT=10 |
| master 接線 | clk_40k -> ADC clock；同時 -> Buffer -> DUT clk |
| ADC DR | 只接內部 debug probe；不直接拿狹窄 DR pulse 驅動 DUT |
| DUT reset | active high，獨立一次性啟動訊號，不是 oscillator |

Buffer delay=100ps 是本次 interface 設計值：比 conversion=50ps 與 DR ready=60ps 都晚，並遠小於 25us。不是已執行後量測出的 latency。兩條分支的實際事件仍要在 500us waveform 核對。

在 ADC pin 的 trigger edge 定義 t_m(k)=T0+k*25us：

| 事件 | 時間 |
|---|---|
| master/ADC trigger | t_m(k) |
| sampling 完成 | t_m(k)+1ps |
| ADC data 更新、DR inactive | t_m(k)+50ps |
| DR ready | t_m(k)+60ps |
| DUT rising edge 消費新 code | t_m(k)+100ps |

官方僅描述 sampling 起迄；ADC aperture 究竟取初端/末端/其他行為，仍應從 autogenerated model 查明。不要把 1ps sample aperture 自動當成已證實的 point sample 方程式。第一筆在整個 aperture 保持 Vin=0；之後確認 sample bus 與理想序列一致。

資料在 DUT 邊緣前已穩定 50ps。保留波形事件時間，確認 Verilog bridge 的 time resolution 沒有把 50ps/100ps 合併；若 bridge 量化時間，應依實際可解析的時間格放大同一組 interface delays 後重新核對，不改 theta 或 golden。這項檢查未在此執行。

## 6. Reset / analog source start

reset 的一次性 PWL：
(0,5V)、(0.49us,5V)、(0.50us,0V)，之後保持 0V。
master 在 1us 前保持低，因此 reset release 不會產生 capture，也沒有 ADC sequence 偷跑。

Analog source：
Amplitude=1 Vpeak（若 dialog 欄位是 peak-to-peak，填 2 Vpp）；
Frequency=60 Hz；Offset=0 V；Phase=0°；無 damping。

測試用 sine start delay **1.000001us**，讓第一個 sampling aperture [1us,1us+1ps] 都是 0V；之後
Vin(t)=sin(2*pi*60*(t-(T0+1ps)))。
這把 sample-completion 當成暫定 stimulus 時間原點。若 generated ADC model 證明其取樣時間在 trigger，應把 source start delay 改為 T0；這是確定 acquisition 時戳，不是在 PLL 加 phase compensation。

SIMPLIS sine 是分段線性表示時，不能只因圖形看起來是 sine 就當成 80000 個 ADC code 與 MATLAB 完全一致。需依本機 source dialog 的實際 waveform resolution 增加分段精度，並先核對 ADC code；Plot Points 不是 source 精度。尚未確認可保證全部 2s code 相同的 source discretization setting，所以不把 analog source interface 宣稱 bit-exact。

若重新 assert reset，必須先停 master 並保持低；重新啟動 golden replay 也要重新開始 source 原點。本次只有 startup reset，不加入運行中的重啟策略。

## 10. Golden 對齊與 FIRST mismatch

以 raw sample index k 對齊。DUT capture 後所有輸出 settle 完畢再取 snapshot；不要在同一 event 的更新前取值，也不要用線性 interpolation 讀 digital bus。

Golden row index（1-based）=k-6，k=7…79999。
5k update index（1-based）=floor((k+1)/8)，只在 k mod8=7 更新。
substep=(k-7) mod8。
comparison time_s=k/40000。若以 waveform 的 DUT capture 時間表示，減去 T0+100ps 取得 sample index timeline；這是時間座標換算，禁止修改 phase expected values。

關鍵格式對應，已讀 exporter source 確認：
- golden pll_phase_anchor = **8 * unsigned(pll_phase_5k)**（Q21 -> Q24）。
- golden held_phase 同上。
- golden extrapolated_phase = theta_40k。
- golden actual_step 與 pll_step_q 都對 DUT pll_step_q。
- 不可拿 pll_phase_post_5k 替代 pre-update anchor。
- 5k/state 欄位先在 pll_update=1 的 snapshot 比對；其間亦可核對保持值。
- 40k delivery 欄位每個 capture 比對，包括 correction_remaining。
- 用既有 golden 原檔作 expected，不重新運算 PLL 或改 CSV。

遇到 FIRST mismatch 輸出：
time_s、k（0-based）、DUT sample number=k+1、5k update index、
signal、MATLAB expected、SIMPLIS actual、
previous MATLAB、previous SIMPLIS，以及當次 ADC code 和 capture timing。
若首列就 mismatch，previous 欄填 N/A。
若 ADC code 不同，先解決 quantizer/source/timing，再判斷 DUT parity。
不能加固定phase offset、移一列、改theta或放宽raw integer比較以掩蓋差異。
